The separate parser finding is tracked in [the rule owner's ledger](../deep-input-rule-bugs.csv); the network lane did not edit or reverify that fix.

## Network fix

| Production path | Enforcement |
| --- | --- |
| Source GET and generic metadata HEAD | `SourceModel.getHttpClient()` and `getHeadClient()` both construct their clients with `SourceHttpPolicy.newClientBuilder()`. The shared directory client also inherits it. Existing GET cache policy, ETag/Last-Modified request construction and HEAD method are retained. |
| Git metadata | `SourceModel.getUrlLastUpdate` dispatches recognized hosts through `GitHostsSource.getSource(url).getLastUpdate()`. The actual GET in `GitHostsJsonApiSource.getLastUpdateFromApi` now uses the same guarded builder. Generating a fixed initial Git API URL alone would not protect a redirected request or a later DNS lookup. |
| Admission and connection | The URL editor and directory reject unsupported remote URLs. The policy checks the initial and every resolved redirect URL before proceeding, including numeric literals which may skip OkHttp DNS. Automatic redirects are disabled. For hostname routes, OkHttp's installed DNS implementation returns the checked addresses themselves; empty, mixed public/non-public, or non-public answers are rejected. There is no separate validation lookup followed by an unchecked resolution. The Android file-picker path remains a `content://` source and never uses this HTTP client. |

**Enterprise/proxy boundary:** Source downloads and metadata refreshes require a direct public HTTPS route. If the system's first route for the original URL or a redirect is an HTTP or SOCKS proxy, the operation fails before that hop is sent, even when DIRECT is listed as a fallback. This includes public enterprise proxies: the app cannot verify which origin address the proxy will use. It does **not** silently bypass the user's proxy. A system-selected DIRECT route is permitted; TLS verification remains in place. This is a compatibility limitation, not a claim of proxy support. Cached content and picker-granted local documents are not evidence of remote reachability.

**Verification:** [DEEP-INPUT-NET-001](../deep-input-net-bugs.csv). In `/tmp/adaway-input-net.F6mFtP`, `:app:testDebugUnitTest --offline --no-build-cache --max-workers=2` with 10 class selectors: **58 executed, 0 failed, 0 errors, 0 skipped**. Nine destination tests and one production-wiring test; 48 supporting tests for conditional GET, directory, Git URL construction, backup and SAF contracts. A real OkHttp route planner, synthetic DNS and a nonconnecting socket double established that a denied redirect answer created **zero sockets**, while each allowed IPv4/IPv6 answer reached the double at that exact address, port 443. Fake responses covered HTTPS redirects, GET/HEAD validators, 304, downgrade denial and the redirect limit. Proxy-first with DIRECT fallback and SOCKS-required initial requests were denied. The Git path is configuration-verified, not tested against GitHub, GitLab or Gist. No real DNS, outbound connection, private-service probe, emulator or live proxy was used in this test lane.

Raw evidence: `app/build/reports/audit-2026-11-25/deep-input-net/` contains `integrated-unit.log`, the ten JUnit XML files and `tested-inputs.sha256`. The routability policy is an address classification, not a guarantee about what a permitted public server serves. Maintain the special-use ranges as assignments evolve.

| Surface | What the code enforces | Concrete residual risk |
| --- | --- | --- |
| Remote source body | `SourceModel.java:1886,1898`: 512 MiB per URL body, checked against declared length and again before each write; missing length does not disable the running count. Failure closes resources and attempts temp-file deletion. | Per-body is not a total staging or free-disk budget. Multiple downloads can await parsing (`SourceModel.java:768,818`). No full-size transfer, unknown-length boundary run or disk-pressure test in this review. |
| Remote directory and Git-hosted source metadata | `MetadataBody.read` caps the decoded body presented by OkHttp before parsing or publishing text: 8 MiB for the whole directory catalog; 1 MiB for each syntax, tag, language, single-list or Git API response. A known oversize length fails before the body is read. Missing lengths (including transparent gzip) still get a running limit; a declared/actual mismatch fails. Directory failure takes the normal IOException path; Discover writes preferences and replaces rows only after all four fetches and parses succeed. Git failure returns no observation: startup and manual checks do not clear the last-good date. No rule entries are rewritten by these checks. | These are per-response byte budgets, not total heap, disk-cache, decompression CPU or JSON object-count limits. Legitimate larger responses, including Gists with embedded file content, are treated as unavailable. No live catalog sizing or low-memory-device test. The separate updater is outside this lane. |
| Picker-granted source document | `SourceModel.readSourceFile` streams the user-granted document through the line-limited rule reader. | **Deferred:** no aggregate byte, elapsed-work or provider-read budget on this local path. Many short valid lines can still require substantial work. Private document grants and their handling were deliberately unchanged; the remote metadata caps do not apply. |
| Source line and rule parsing | `SourceLoader.java:475,494`: chunked reading; maximum 65,536 characters per line before enqueue. Mixed sources can import recognized rules and count skipped lines. A nonempty set of rejected lines with zero inserts fails; staging is cleaned before promotion (`SourceLoader.java:187,212`; targeted update in `SourceModel.java:1603,1661`). | Queue capacity is in items, not bytes. Empty/comment-only input does not satisfy the all-unsupported failure condition; a successful empty revision is possible. Decide explicitly whether previously nonempty protection may be replaced with zero rows. The importer is not a browser-rule engine. |
| Backup import/export | `model/backup/BackupImporter.java:84,103,150` reads UTF-8 with a 16,777,216 decoded-character limit before JSON parsing, validates before mutation, then applies rows transactionally. `BackupFormat.java:25,51,73,119` limits sources to 200 and combines rules across all three lists for a 50,000 total; it validates rule kinds/targets and disables restored source redirect mode. Export validates before opening the destination (`BackupExporter.java:94`). | These are not peak-heap limits. The JSON tree is built before row-count checks; export materializes rows and formatted JSON before the final size check. Low-memory behavior, provider write interruption, and post-commit cache-rebuild failure were not tested here. Backup redirect-target unit tests do **not** test HTTP redirects. |
